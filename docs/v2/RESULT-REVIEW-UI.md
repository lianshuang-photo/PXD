# 候选审阅界面

本模块以 #69 的[共享结果审阅](RESULT-REVIEW.md)为前置依赖，将相同 HTTP/MCP 状态接入 LS Studio 专业工作区。不更改根 PXD 应用、后端 schema、生成或 Photoshop 执行器。界面同时影响浏览器预览和 Photoshop UXP 面板，浏览器验证不能替代原生面板验收。

## 路径与影响清单

从「任务与候选图」选择任务及候选 → 查看原输入／候选 → 按区域记录多条反馈和希望保留的内容 → 保存共享反馈。采用或取消采用是单独操作；查看此前采用版本会定位到祖先任务的具体候选，且不生成、不回贴、不撤销 Photoshop 修改。

- `studio-review-014.js` / `.css`：审阅模块、同一连接内的本地反馈编辑、读写确认与恢复。worker 独立负责模块和针对性测试。
- `studio-results-014.js`：公开当前候选选择并通知工作区。两个候选即使共用同一图像资产，也按任务／候选身份通知。
- `studio-014.js`：集成人负责挂载、跟随选择、沿用工作区轮询、连接切换／销毁，以及此前版本导航。审阅表单独立于会因轮询重建的候选缩略图列表。
- `index.html`：加载模块及样式。沿用原有字体、颜色、缩放变量、纵向滚动和 `ui.createButton` 的键盘／禁用行为。
- 新增控件为文本输入、分类 select、普通多行 textarea 和按钮。反馈 Enter 用于换行，不套用专业指令的 Enter 运行行为。原生 IME、焦点、select、按钮及浅／深色 × 100%／200% × 常规／窄面板均须另行验证。

## 共享状态与恢复

反馈完整编辑 `items`（最多 20 项）和 `preserve`（最多 20 项），不将 Agent 保存的多项记录缩成一条。区域、分类、描述、修改要求分别保存；删除反馈与取消采用相互独立。未保存内容按任务／候选保留；轮询、切换候选和 Agent 的更新不得静默覆盖。

审阅使用独立的 review revision，与当前生成草稿的 dirty／revision／冲突无关。版本冲突保留本地文字，并提供明确舍弃本地、读取当前审阅的入口。界面不会把服务器新 revision 自动套到旧意见上覆盖他人修改。

网络中断、确认数据无效或存储确认失败时，显示「保存尚未确认」，并保留原 operation、requestId、expectedReviewRevision 和内容。用户核对时先读回，再显式核对原请求；同一任务在核对前不能提交另一审阅写入。合法去重响应返回的是当前审阅，不能把此前提交的内容误显示成当前状态。

核对重试在请求去重前被拒绝（例如服务正在关闭），不能据此断言第一次请求未保存。原请求继续待核对；若原样重试得到合法、匹配任务且 revision 更高的版本冲突，则依据服务「原子去重先于 CAS」的契约确认原请求未写入，转为可重新载入的冲突状态。本地意见仍保留，错误详情缺失时不能作此确认。

本会话按 Companion 连接隔离编辑和待核对请求；同一服务重连保留它们，不向不同服务自动重放。过期读取和写入响应受连接生命周期保护，不回填新面板，也不能让较旧 review 覆盖已确认状态。销毁／整页重新加载不保存本地编辑日志；服务器已保存的审阅会重新读取。

祖先采用记录可能在当前任务 revision 不变时更新，因此仍随工作区刷新读取。导航前检查祖先任务及候选存在；不可用时保留当前位置并显示可操作提示。

工作区轮询失败单独提示未读到工作区，恢复读取后清除该读取错误。它不表示审阅、生成或回贴提交失败，也不能清除这些写操作仍待确认的状态；审阅保存恢复后的成功提示不能与旧的读取错误相互矛盾。

## 验证与门禁

自动化覆盖模块的多项反馈、并发版本冲突、未确认请求、晚到响应、同服务重连／跨连接隔离和实际工作区挂载联动。FakeDOM 只能验证状态与事件接线，不具有 UXP 字体、布局、原生输入或 DPI 能力。

最终源码、独立 review、浏览器真实交互、PS 后端和原生面板结果分别写入后续验收记录。此说明不是验收通过证据；main 仍要求最终 head 的 CI、独立审批、已解决讨论和 `ls-studio/computer-use`。新模块先提交独立依赖 PR，再纳入私有 M1 组装分支，不能合并到临时比较 base 代替 main 流程。
