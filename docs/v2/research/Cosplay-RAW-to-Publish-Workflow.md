## 1. 结论与证据边界

**有相关资料，足以搭建流程骨架；目前不能说已有一套可以直接照搬的完整 COS 生产 Skill。**

公开资料中既有 Camera Raw → Photoshop → 发布前处理的完整单张案例，也有中文 COS 精修、补妆、发丝、合成和正片排版教程。Adobe 官方资料能够校核无损编辑、组图比较、参数同步、色彩配置和输出锐化等基础规范。

资料的缺口主要是：同一作者怎样在不同原片之间选择方法，角色还原与 coser 本人特征之间如何取舍，怎样判断已经修够，以及真实返修怎样改变下一步。单张演示也通常不覆盖素材管理、整组定调、审片、排版交付和归档。

本报告中的端到端流程是这些资料与通用摄影交付方法的综合建议，**不是声称全行业存在一条固定流水线**。选片、样片确认、反馈记录等生产组织建议会明确说明；不能把单个作者的参数、修图强度或快捷习惯升级为通用标准。

## 2. 从原片到发布的完整流程

这里的“原片”泛指未经本次后期的输入，可能是相机 RAW、JPEG、TIFF 或已有 PSD。只有真实 RAW 才涉及完整的 RAW 显影余量；对 JPEG 使用 Camera Raw 滤镜，不等于恢复相机 RAW 信息。

目标需要先分支：漫展场照侧重干净、人物表现与效率；角色正片强调角色辨识度和组图表达；幻想合成还需要场景设计、素材与光影融合。高强度修脸、换背景、特效、长条排版都是可选分支。

| 阶段 | 要做的工作与关键判断 | 应留下的结果／完成依据 |
|---|---|---|
| 1. 整理输入 | 保留原片，建立工作副本或非破坏编辑记录；对应拍摄组、文件编号、参考图和现有修订。确认输入格式、清晰度及可修复范围。 | 原片清单与可追溯的工作文件；不会把低清聊天预览误认成最终素材。素材管理是本报告的生产组织建议。 |
| 2. 明确本组目标 | 明确角色及版本、故事／情绪、参考中要借用的部分、修图强度、保留的人物特征、交付张数和发布形式。已有拍摄策划时继承它。 | 一份简短的目标与保持项；参考图不能自动变成对脸型、服装或构图的全面替换授权。[S1][S2][S3] |
| 3. 选片与编组 | 先排除技术失误，再比较表情、姿态、角色感、服装完整度和构图潜力。组图还要有景别、动作、视线或叙事上的变化；按不同光线／场景编组。 | 待精修片单、候补片及初步顺序；选中原因可说明。清晰度与故事潜力见个人案例 [S9]；整组组织方式是本报告建议。 |
| 4. RAW／基础校正 | 检查白平衡、曝光、亮暗部、色偏、镜头问题与噪点；进行必要的裁切和画面校正，为后续精修保留可用层次。可以预设大致气氛，但应留有调整余地。 | 可继续精修的底片及处理记录；区分基本纠错和创意调色。依据 [S1][S10]，不要求所有滑块都调整。 |
| 5. 做代表样片、确定风格 | 选一张能代表本组问题的照片先走完主要处理，确定脸部与皮肤强度、发色／服装色、明暗、氛围及特效方向；不同光线组可能需要各自样片。 | 用户认可的样片、参考和修改意见。先试修再推广是减少整组返工的建议；组图参照与比较有 [S11] 支撑。 |
| 6. 人物与角色精修 | 按需要处理痘印、汗光、底妆斑驳、肤色不连续；修补眼妆、唇妆、睫毛、瞳色；整理假发穿帮、杂发和发型轮廓；修正服装接缝、扣件、折痕及道具瑕疵。五官／体态／服装轮廓调整按已确定目标执行。 | 单张人物既符合所选角色表达，也符合约定的本人特征与修图强度。不能默认所有人都需要放大眼睛、瘦脸或瓷化皮肤。[S1][S2]；中文专题存在性见 [S4][S5]。 |
| 7. 塑造光影与材质 | 局部处理脸部体积、人物与背景分离、服装／金属／武器的明暗与质感。根据材质分区，避免全图一套“提亮、磨皮、加清晰度”。 | 缩到整体看主体仍清楚；放大看没有光晕、脏块和材质互相混淆。[S1][S2] |
| 8. 按需合成与特效 | 清理环境穿帮、补／换背景、加入角色元素、天气或能力特效。核对大小、透视、遮挡、光向、接触阴影／反射、环境染色、景深、锐度与颗粒。 | 新元素在空间和画质上融入照片，并服务于角色与画面主次。[S1][S2][S3][S9] |
| 9. 终调与整组统一 | 回到整体检查色调、肤色、角色标志色、反差和氛围。参考样片匹配各张，按光线差异调整；可同步共同设置，局部问题逐张修正。 | 单张成立，放在一起也像同一组作品；一致性不等于复制所有数值。[S2][S10][S11] |
| 10. 审片与返修 | 从整体、100% 局部和目标发布尺寸检查。核对脸型／身份偏移、妆面、发丝和蒙版边缘、液化导致的背景弯曲、重复纹理、色带、光效与文字问题。把反馈指向具体图片、区域与版本。 | 已认可的精修母版，以及必要的修订记录；不要用“工具返回成功”代替成片验收。迭代比较见 [S1][S2]，版本组织是本报告建议。 |
| 11. 正片组织与排版 | 根据目标决定单图、图集、封面、九宫格或长条；安排图片顺序、留白、文字与图形。按项目约定核对作品／角色名称、CN、摄影、妆造、后期等署名。 | 能在实际浏览尺寸下阅读的发布稿。排版作为独立 COS 工作的资料见 [S6]；不是每组都要做长条。 |
| 12. 导出、发布检查与归档 | 从母版生成对应平台／用途的输出副本，设置像素尺寸、格式、压缩、色彩配置、输出锐化和水印。检查实际导出文件的清晰度、颜色、裁切与文字；保存原片、工作文件、样片、最终输出及版本对应关系。 | 可发布文件和可再编辑母版。网页图通常以 sRGB 作为兼容性起点；印刷另按印厂尺寸、配置文件等要求处理。[S12] |

### 顺序中的真实依赖

- **大方向先于精细劳动。** 如果要大幅换景或重构画面，先做构图和光影草案，再精修最终会保留的部分；不要把“合成”机械地固定在所有精修之后。
- **大结构改变会影响已有细节。** 裁切、变形、抠图和大面积生成可能使之前的蒙版、发丝修补失效，应先评估依赖再排序。
- **基础校正、创意调色和输出处理是不同任务。** 前期可以定调，后面仍需因合成和局部修整复查；网页输出锐化应针对最终尺寸检查。[S1][S10][S12]
- **样片需要用户审美反馈。** 参考匹配能够验证统一程度，无法代替用户对“像不像角色”“是不是我想要的脸”的判断。
- **发版不是另存为 JPEG 即结束。** 组图的选择、顺序、排版、文字和目标平台的实际显示，都会改变最终作品。

## 3. 完整案例能告诉我们什么

### KamuiCosplay：Aloy 原片到雨中场景

[How to Edit your Cosplay Photos - Tutorial](https://www.youtube.com/watch?v=7oCul1Bd7tY)，Benni / KamuiCosplay，2018-11-04。以下基于完整自动字幕归纳，时间只用于回查。

| 时间位置 | 作者实际说明的处理 | 可复用的判断 |
|---|---|---|
| 约 0:36–4:13 | 在 Camera Raw 中把阴天原片向阴冷、戏剧性的雨天方向处理，并比较调整前后。 | 先知道要表达的场景，再选择白平衡、明暗和氛围；调节时注意人物肤色受影响。 |
| 约 4:50–9:12 | 处理蚊虫叮咬、头盔牵拉产生的局部问题和服装外露扣件。 | COS 精修对象包括拍摄／穿戴穿帮，不能只做通用磨皮。 |
| 约 9:30–10:55 | 用液化收整破坏轮廓的衣料折起处。 | “液化”可以服务于服装轮廓；不能把工具名直接等同于人物瘦身。 |
| 约 11:19–16:37 | 分别处理护甲、脸部和红发，让主体更突出、发色更接近角色，同时顾及雨天气氛。 | 人物、头发、金属等区域需要不同目标；角色色彩还要与环境一致。 |
| 约 16:40–23:18 | 加入前后两层雨，调整大小、透明度、虚化和遮挡，减少脸上干扰。 | 特效的空间层次和主次，比“有没有雨”更重要。 |
| 约 23:22–33:57 | 加入游戏机械兽；匹配比例、虚化、黑位、环境色、树枝遮挡及颗粒。 | 合成失败需要按具体维度诊断，不能仅再次要求“更真实”。 |
| 约 34:28–36:21 | 说明先保存，再为上传压平、缩图与锐化。 | 编辑母版与发布输出应分开；输出效果要在最终尺寸检查。 |

不能照搬的部分：

- 视频里的模糊半径、噪点百分比和锐化程度只服务于该案例，不能成为任意尺寸照片的常数。
- “72 ppi 是屏幕图片要求”的说法不能当作通用规范。Adobe 将像素尺寸与面向印刷的 ppi 设置分开说明；网页应关注实际像素尺寸、显示和压缩。[S12]
- 为演示节奏省略细修、用橡皮直接擦除等做法，不应变成 Agent 的默认生产策略；可编辑图层、蒙版和明确版本更适合返修。

### Daniel Grove：角色要求会改变“正确”的修图强度

[My Photoshop Secrets for cosplay & creative photography](https://www.youtube.com/watch?v=xt8ML4gc8LY)，2023-09-16。

- 约 12:20–16:45：用曲线和蒙版做非破坏加深减淡，处理已有明暗与人物体积；这提供了局部光影任务的实际语境。
- 约 21:19–23:44：整体 LUT 可以建立氛围，但会影响皮肤及服装颜色，需要局部控制。组图风格不能以牺牲关键颜色为默认代价。
- **约 25:12–26:20：作者说明自己通常不喜欢过分瓷化的皮肤，但这张是人造人 2B，因此有意比普通人像处理得更平滑。** 这直接说明皮肤质感是角色、照片和目标共同决定的，不能硬编码成一种审美。
- 约 32:05–35:28：光剑颜色、发光与环境融合服务于具体角色版本；“加一个发光素材”尚不构成完成。
- 前段清理杂物时，内容识别会带入错误纹理，需要进一步修补。模型或工具执行完毕后仍要看结果。

这些是作者的案例决策，不是要求每张 COS 照都使用 LUT、频率分离、加深减淡或魔法特效。

## 5. 现有 Skill 的覆盖与缺口

已核对 cos-effect-prompt/SKILL.md（来源 `LOCAL_COS_SKILL/SKILL.md`）。其定位明确是 **Nano Banana／Gemini 图像编辑提示词编译器**，能够生成、反推、诊断、迭代已有图片的编辑指令，不直接执行 Photoshop。

| 能力 | 当前可以复用什么 | 本次发现的缺口 |
|---|---|---|
| 理解单张修改要求 | 目标、范围、保持项、参考归因、条件动作和结果验收 | 从“已有明确修改要求”往上，增加原片诊断、优先级、工作阶段和下一步判断。 |
| COS 局部知识 | 人物、皮肤、头发、服装、背景、调色和 VFX 的参考模块 | 在真实案例中验证角色和风格分支，尤其自然／角色化／高强度绘修的不同完成标准。 |
| 失败处理 | 能按失败 operation 修改提示词 | 还需要区分原片问题、审美问题、工具失败、合成失败，以及该回到哪个阶段。 |
| 连续生产 | 当前围绕一次图片编辑输出 | 缺素材与片单、代表样片、整组一致性、版本返修、发布组织、输出与归档。 |
| PS 执行 | 另由 photoshop-use、MCP 和 UXP 负责 | 当前已接观察／定位，真实编辑、准确回贴和回滚尚未完成；写进 Skill 不会自动获得这些能力。 |

现有 Skill 中“皮肤保留毛孔尺度”等规则适合其默认目标，但不宜未经分支地当作全部 COS 风格的绝对审美标准。可以保留身份与未请求区域的控制，同时依据用户明确目标允许更平滑或绘画化的结果。[S2]

架构上仍可保持此前的两种职责：

1. **COS 领域 Skill**：理解角色与交付目标，诊断照片、选择阶段和处理强度、设定视觉验收、处理返修。
2. **Photoshop 执行 Skill**：选择当前真实支持的工具，管理文档／图层／蒙版／作业，读回结果并保证可恢复。

两者运行在同一个外部 Codex harness 中。现有提示词编译器可作为领域知识及图像模型路径的专门模块继续复用；不必为这次调研强行改写 V2，也不需要拆成两个独立 Agent。

## 6. 对 LS Studio roadmap 的修正建议

此前的“选区提亮 → 调整层＋蒙版 → 接受／撤销”是有价值的工程验收，但它证明不了产品已经能够完成一次 COS 后期工作。

**建议把下一产品里程碑设为：一组真实 COS 原片，经过代表样片、返修和整组统一，交付可发布的成片。** “一组”是工作目标，不要求第一版立刻实现复杂批量工作台；可以先通过一张样片，再验证同组其他照片。

建议实施顺序：

1. **建立真实案例与完成标准。** 选择用户具有目标参考的一组照片，记录原片问题、希望保留／改变的内容、样片、返修意见、最终发布形式。先完成生产拆解，避免用任意测试 PNG 定义产品审美。
2. **让现有 Agent 参与样片流程。** 利用已经打通的文档、图层与画面读取，理解角色目标、指出真实可见问题，给出有优先级的修图步骤，保存这张图的阶段和反馈。看不到的区域或原片信息应明确标记。
3. **从样片倒推第一批编辑工具。** 根据案例优先接入所需的选区／蒙版、局部色光、人物或服装修整、素材回贴等能力；原生调整与图像生成根据任务选择。源文档绑定、无损工作层、错误识别、结果读回和精确撤销是执行基础。
4. **验证推广与交付。** 把已认可的样片用于同组其他照片，验证颜色与人物风格一致，支持定向返修，再生成实际需要的封面／排版和输出文件。
5. **从经过验证的决策整理 Skill。** 不要求先写完一套大 Skill 才能继续 Agent 集成；但每新增一种能力，都要能说明它解决流程中的哪个问题，以及如何验收。

相应地，产品需要理解的对象至少包括：照片／组、角色与风格参考、代表样片、阶段、修改记录、认可版本、发布输出。第一版可以用轻量文件和对话上下文表达，不必立即增加大量新页面。

Camera Raw／Lightroom 可以承担显影、选片和组图管理的一部分；LS Studio 不必吞并所有软件。它需要知道接收到哪一阶段、输入与输出是什么，以及下一步怎样衔接。没有验证的 ACR／LR 自动化能力也不能先承诺已经支持。

## 7. 是否值得用课程“蒸馏” Skill

**值得，但选课依据应是“能不能提供判断与纠错证据”，而不是课时长或操作数量。** 公共材料足以建立初版流程；课程更适合补用户希望追随的中文 COS 审美、系统精修和连续案例。

优先选择能提供以下信息的课程／案例：

- 从真实原片开始，有明确角色版本和目标成片；风格与用户希望的结果接近。
- 有正常速度的口述或清楚的时间标记，解释为什么先做这一步、为什么不用另一种方法。
- 能查看关键中间态和分层 PSD／蒙版／参数；只有最终 JPEG 或高速录屏很难判断因果。
- 有不同脸型、妆面、光线、服装材质和背景条件；最好有同一组多张照片，能观察哪些设置可复用、哪些必须重新判断。
- 包含做错、过度、返修与停止的例子，而不只是一次顺利演示。
- 明确覆盖成套定调／返修／排版交付的哪部分；基础 PS 按钮课程不能自动补上 COS 审美知识。

建议提取的最小知识单位：

> 输入条件／可见问题 → 创作目标 → 为什么选择这种处理 → 可执行步骤 → 中间检查 → 完成或失败标准 → 失败后的回退或替代方法 → 来源时间点。

例如可从 [S1] 的雨层处理中提取：背景虚化、人物清晰 → 雨要有前后空间 → 分前后层并分别匹配虚化／遮挡 → 检查是否盖住脸和产生重复拼接 → 仍像贴图时先修景深、尺度和边缘关系。不能提取成“所有雨特效统一 Gaussian Blur 13 px”。

可执行的验证办法：

1. 选少量完整案例，先人工标注关键决策和前后变化；这是方法提取，不是训练新模型权重。
2. 归并稳定规则，保留风格分支和适用条件；把纯软件操作放到 PS 执行参考，避免在领域 Skill 中堆一份 PS 手册。
3. 在未用于提取规则的照片上试用，让用户比较角色感、本人特征、修图强度、材质与融合、整组一致性。
4. 记录 Agent 选错步骤、修过头、未达到效果和不知何时停止的情况，用失败案例修正规则。工具调用成功率单独记录，不能充当审美通过率。
5. 真正能够稳定复用后，再整理入口 SKILL.md、按阶段加载的参考模块和少量示例；本次先保留调研与案例索引。

目前可以确定“资料存在、流程可以建立”；尚不能确定公开资料是否足以覆盖用户全部审美，也不能在未看课程内容和案例前推荐某套付费课作为唯一答案。
