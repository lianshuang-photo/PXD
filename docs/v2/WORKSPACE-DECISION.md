# 工作区决策：PXD V2 与 LS Studio

日期：2026-09-20。结论：**沿用 PXD 仓库；独立 V2 工作区与应用目录；实现待用户确认。**

## 事实依据

1. PXD 仓库属于同一个 Photoshop 创作产品方向，保留了图像引擎、生成任务、Photoshop 执行、预设、镜头、分块和排版的历史代码与问题记录。
2. 核对时 GitHub main 为 `3c9fc7d`。本机旧 checkout 为 `000df5b`，落后 7 次合并；此次只 fetch 更新远端引用，没有切换或覆盖旧 checkout。
3. GitHub 仍有 4 个开放的旧功能 PR：#42、#43、#46、#48；#44、#45、#47、#49 已关闭但未合并。旧 issue #25 的部分勾选和“open”文字已过时，不能直接作为实施依据。详情见 [复用清单](LEGACY-REUSE.md)。
4. LS Alpha 0.1.5 没有 Git 元数据，当前已验证的 UXP UI 与真实 Codex 接入是另一个代码目录中的资产。两条代码线需要统一管理，但不能把它们当作已经集成。
5. 没有发现需要独立所有权、独立团队权限或完全独立产品生命周期的现有要求。

## 方案比较

| 维度 | 同仓 PXD V2 | 新建 LS Studio 仓库 |
|---|---|---|
| 产品连续性 | 延续 PXD 的 Photoshop／AI 创作方向 | 需要解释两个产品及迁移关系 |
| 历史与复用 | 可引用固定 commit、旧 issue／PR，分模块移植 | 需要跨仓搬运并维护来源对应 |
| 技术隔离 | `apps/ls-studio/`、独立运行边界与 worktree 足够 | 仓库隔离直接，但不能自动解决运行时兼容问题 |
| 维护成本 | 同一套需求编号与后续验收 | 容易形成两套路线图、issue 和版本状态 |
| 主要代价 | 仓库会暂时同时存在旧应用与新应用，需清楚标注 | 旧积累被割裂，仍要回头核对旧代码 |
| 适用条件 | 当前同一产品演进 | 将来独立团队／权限／分发需求确立时再考虑 |

因此选择同仓。无需因为从 React／TypeScript 转为已验证的 UXP DOM 面板＋Companion，就另立产品仓库；也不因沿用仓库而强迫新面板重新套用旧 UI 技术栈。

## 目录与工作区

当前已创建的本机规划 worktree：`~/Developer/PXD-v2`，分支 `codex/pxd-v2-planning`，基于上述 GitHub main。旧 `PXD-codex` 以及 24 个历史 issue worktree 保留。

确认后采用以下布局。标为“计划”的目录不表示本次已经创建或导入。

```text
PXD/
  src/                       # 既有 PXD React/TS 应用，初期保留
  public/ manifest.json ...  # 既有应用构建入口
  docs/v2/                   # V2 需求、契约、路线图、验收的主来源
  apps/ls-studio/             # 计划：从 LS Alpha 导入
    package.json             # 计划：明确独立模块作用域，避免继承根 type: module
    plugin/                  # 当前已验证的 UXP 面板及宿主执行器
    companion/               # Codex 会话、共享任务、供应商、MCP
    scripts/
    tests/

```

`docs/v2` 不依赖个人绝对路径或私有任务链接。历史本机审计证据保留在本机，公开版只保留可核查的来源标识、相对路径或公共 URL。

## GitHub 管理方式

- 当前使用一个文档 draft PR 供用户审阅。此次不修改 main、默认分支、仓库权限或旧 PR 状态。
- 确认后按 G00 导入 LS 基线，开独立 PR；再按小型任务分支推进。日常 PR 以已合并基线为起点，不创建长期相互堆叠的 issue 分支链。
- 旧根目录应用保留，直到 V2 迁移和发布有明确验收；不在初始化时删除旧代码或历史 worktree。
- 新任务统一使用 `V2` 前缀与 Gxx 工作包编号。旧 issue #1–#24 的状态不直接改成 V2 完成；需要复用时建立对应关系。
- 尚未创建远端 milestone／issue；文档先明确工作包，用户确认后再落为任务，避免未确认计划占满看板。
- 所有开发 PR 保留供用户审阅；不自动合并。主 agent 管理集成，subagent 不直接推 main。

## 导入与运行迁移

G00 顺序：

1. 以 `baseline/ls-alpha-0.1.5.json` 记录的文件哈希核对 Alpha 源码；只导入应用代码、必要静态资源、脚本和测试，记录来源。第三方预设／字体／代码的来源与许可要单列，不能因为新目录名就认为已经重新授权。
2. 保留当前 UXP 入口 `*-014.js/css`，不把无后缀备用文件误当主路径。独立 package 作用域中验证 Node CommonJS／ESM 边界；不把目录迁移夹带成前端框架重写。
3. 更新运行脚本与文档引用，完成现有回归测试。发布清单仍保持 0.1.5 基线，功能版本在对应交付中再更新。
4. 使用隔离的 `PXDLS_AGENT_DATA`、端口和测试文档验证导入副本；不能让并行 agent 共用生产会话数据或同时控制一个 Photoshop。
5. 需要切换到新工程时，再从新路径更新 Companion 运行副本、重新加载 UXP manifest，并验证会话恢复与 PS 观察；不在此次文档工作中重启用户服务。
6. 成功切换后，Downloads 副本改为来源快照，只保留迁移说明。保留原数据以便回退，后续源码只在 Git 工作区修改。

目前运行副本仍由 Alpha 的启动脚本安装到 `~/.pxdls/service/runtime/`，会话在 `~/.pxdls/agent/`。运行数据、凭据、生成图片和私人 PSD 不进入 Git 仓库。
