# PXD V2 · LS Studio 产品需求

版本：0.6。更新：2026-09-20。状态：待用户审阅；当前运行实现仍为 LS Alpha 0.1.5。

## 1. 定位与目标

LS Studio 是在 Photoshop 中工作的创作工具：专业可视化工作区与 Codex Agent 使用同一套能力、参数、素材和任务，用户与 Agent 可以接续完成 COS／角色照片的精修、合成、调色和发布准备。

仓库沿用 PXD，当前 LS 作为 V2 应用独立导入。具体决定见 [工作区](WORKSPACE-DECISION.md)。保留已验证的面板、会话和观察链路；复用 Codex harness，不自建另一套 Agent 循环。

产品用两条标准同时验收：

1. **能力覆盖**：轮椅中有价值的创作玩法全部进入 B01–B36 [能力台账](CAPABILITY-MATRIX.md)，交付时间按依赖分阶段安排。
2. **实际生产**：一组 COS 原片 → 目标／选片 → 样片 → 精修／合成 → 整组统一 → 返修 → 发布输出，验证工具能否共同完成作品。

单张工具演示、配方数量、成功 HTTP 返回或一次模型出图，均不足以代替上述验收。

## 2. 用户与核心操作

- 用户可以直接在专业工作区选择部位、装入配方、改参数、摆灯、组织参考图、查看任务与结果。
- 用户也可以让 Agent 读现场、理解角色目标、选择合适能力、修改参数并执行；Agent 读到的状态与专业页显示相同。
- 用户手动调整后，Agent 可以继续；Agent 执行后，用户可以直接改参数、比较候选和返修。
- 所有编辑有明确来源、结果和恢复方式；重启恢复不偷偷换用当前照片或最后一次全局抓图。

灯光示例：用户在可视画布摆主光和轮廓光 → Agent 读取同一份灯具参数并减弱主光 → 运行图像编辑 → UI 显示候选 → 选择结果贴回原文档 → 用户继续调色温或撤销这次修改。参数、任务和结果不通过复制一段文字来接续。

## 4. 完整范围

| 能力组 | 内容 | 台账编号 |
|---|---|---|
| 现场与素材 | PS 观察、生产抓图、真实选区／蒙版、明确整图输入、多参考归因、补白和返回逆变换 | B01–B03、B35 |
| 配方与领域理解 | 分类检索、完整参数、预设管理、可点击人体部位、提示词生成／反推／诊断／迭代 | B04–B07 |
| 编辑与任务 | BYOK、图像编辑／文生图、候选、回贴、历史、批处理、取消／恢复、资源诊断 | B08–B14、B32–B34、B36 |
| 专用创作 | 2D／3D 灯光、镜头、半合成／地台／垂悬、场景、VFX、调色、色彩匹配、示波器、海报 | B19–B28 |

Forge、ComfyUI、人体剪影、批量、节点和排版都保留在总范围。旧 Alpha 文档中的“不做／不接”只描述当时范围，不再作为 V2 排除依据。

不需要继承的内容：原插件的广告、积分充值、强制公告、作者账号、打赏、遥测或特定代理服务。BYOK 和用户选择的端点继续成立。灯具、镜头和节点保留适合的专用交互，不统一压成普通表单或按钮列表。

## 5. 首个真实编辑交付 M1

用户在 UI 或 Agent 中明确当前文档与输入范围，装入配方／指令和参考图，通过真实供应商得到候选，选择回贴、比较、认可或撤销；另一入口可以接续同一个任务。

必须包含：

- 输入固定为可追溯资产：生产像素、真实 mask、源文档与预期版本、参考用途、参数和设置快照；预览图与生产输入分开。
- 默认跟随用户明确的选区；整图处理是显式模式。无选区时给出选择范围或整图模式的入口，不能静默扩大范围。
- 图像编辑与原生 PS 调整分别声明能力；不能把所有指令都送给图像模型，也不能在失败时退回 mock 并报告成功。
- 首个 BYOK 适配器明确 endpoint、model 与能力；Codex 对话认证和图像供应商凭据分别处理。供应商未配置时明确显示不可运行。
- UI 和 Agent 读写同一个草稿版本；执行固定快照。运行时编辑参数属于后续版本，不改变正在运行的输入。
- 候选可保留、比较和手动回贴。回贴失败单独重试，不重复生成。取消后的迟到结果不能自动写 PS。
- PS 修改绑定来源，在 modal 内再次校验；新建层和修改原层分别记录。撤销恢复本任务的修改，不能统一删除“最后结果层”。
- 重启后可以恢复任务和结果；远程请求状态不明时明确标记待核对，禁止盲目重发收费请求。
- 完整配方参数与参考图实际影响请求；自动回贴、编组、图层类型等设置需要真实执行证据。

详细验收见 [VALIDATION](VALIDATION.md)。首个案例使用一组真实 COS 照片中的代表样片；M1 不宣称已经完成整组排版、批量和所有高级玩法。

## 6. COS 生产上下文

领域上下文记录角色／版本、本人特征保持项、风格强度、参考用途、代表样片、当前阶段和反馈。自然场照、角色化精修、高强度绘修、幻想合成采用不同完成标准，不默认全局瘦脸、瓷化或加特效。

工作流不是固定滤镜顺序。大幅换景应先确定构图与光影，基础校正、创意调色和输出锐化分别处理。整组一致性按样片与光线分组验证，不能直接复制所有局部蒙版。

RAW 显影、选片和归档允许与 ACR／Lightroom 等外部软件衔接；LS 记录输入、阶段和输出，不先承诺尚未验证的 ACR／LR 自动化。课程／案例用于补充判断与纠错知识，不代替执行工具实现。

## 7. 运行与架构原则

- 专业 UI、Agent MCP 调用统一 capability handler；每项玩法有可序列化参数、能力限制和错误。
- Companion 管理资产、任务、供应商与 Codex 会话；UXP 执行 Photoshop 语义操作。长生成任务与短 bridge 请求有不同生命周期。
- COS Skill 管目标、阶段和审美验收；PS Skill 管动作选择、图层／蒙版、读回和恢复。由同一个 Codex harness 按需使用，不要求两个独立 Agent。
- 每个工作区可以有专用交互，但共享任务、资产和结果服务；不能各造一套状态与历史。
- UI 保留目前已验证的 UXP 兼容性；运行逻辑不依赖 Chromium 专有行为。浏览器预览通过不代替 Photoshop 真机验证。

契约及新模块路径见 [ARCHITECTURE](ARCHITECTURE.md)。实施范围内没有“任意模型生成脚本直接在 PS 运行”的默认入口。

## 8. 完成定义与文档权威

一个玩法只有在可视操作、Agent 接口、真实执行、双向接续、正确失败／恢复、真机及视觉验收全部具备时才能标记完成。旧 PXD 的已合并状态只是复用来源证据。

完整能力范围以本 PRD 与能力台账为准，交付顺序以路线图为准；接口事实以实际注册工具／实现及验证记录为准。历史审计保持原日期，后续更正附带日期，不回写为已实现。

本次由用户要求先评估工作区和同步文档，待其看完确认后再安排 subagent。因此此文档定稿前，不启动 G00 之后的开发工作。
