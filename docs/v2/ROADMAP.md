## 依赖与并行

G00 导入后先由主 agent 完成 G01 契约和模块骨架。G02 任务／资产、G03 PS 执行、G04 供应商可以在契约稳定后并行；它们的合并与真机写入串行管理。

G05 专业 UI、G06 Agent 工具、G07 配方与 Skill 在上述接口可用后接线，G08 执行跨入口验收。可以先用 fixture 验证边界，但 M1 完成必须有真实供应商和 PS 案例。

M2 及之后的专用 UI 依赖共享能力，但算法研究／旧代码复用评估可在合适时提前进行。提前研究不增加未交付能力的完成度；不得跳过共享状态系统再新增孤立玩法。

B05 已利用共享基础提前完成实现，保持为 G09 的独立子项，人体剪影／17 部位导航 B06 尚未开始。M2 仍须等待对应阶段的完整案例和宿主验收，不能由预设管理一项推导为通过。

## 首个 M1 案例

一张有明确参考和保留项的 COS 样片：在专业页准备输入与修改目标 → Agent 读取并调整同一份参数 → 真实生成候选 → UI 比较并回贴 → 用户反馈局部问题 → Agent 对同一任务派生修订 → 可恢复到此前认可版本。

优先覆盖范围控制、参考归因、一个实际局部编辑及原生色光调整。具体修图目标由样片决定；不预先要求加魔法或换背景。最初案例不强制等到高级灯光画布建完才运行。

## 阶段完成门槛

1. 实现、UI、Agent 三者指向同一能力和状态。
2. 自动化覆盖该阶段的失败与恢复边界；没有以 fixture 代替 live 成功记录。
3. Photoshop 验证使用测试副本，保留输入、输出、操作回执与视觉判定。
4. 相关 Bxx 台账和验收证据同步；未完成分项保持明确待办。
5. PR 描述标明真实验证、尚未覆盖内容和复用来源，交给用户审阅，不自动合并。

不承诺基于按钮数量或配方数量的完成百分比，也不使用旧 issue 标签中的工期估计作为本轮排期。
