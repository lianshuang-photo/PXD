## M0／M1 验收表

| ID | 场景 | 通过条件 |
|---|---|---|
| V01 | 套索、孔洞、羽化和部分透明选区 | 生产输入与实际 mask 对应；结果按真实边缘回贴，选区外不被覆盖 |
| V02 | A 文档启动后切到 B，或 A 关闭／重开 | 不错抓／错贴；重新打开不只凭旧 documentId 判断身份；结果可保留 |
| V03 | 无选区与明确整图模式 | 未明确范围时请求选择，显式整图时才整图处理；无静默扩大 |
| V04 | 修改已有层后撤销 | 恢复原属性／效果，原有层存在；遇到后续用户修改时报告冲突，不粗暴回滚 |
| V05 | 残留配方后执行接受、撤销、读回 | 不生成新请求，不额外回贴；控制操作有独立语义 |
| V06 | 供应商错误、batchPlay 错误与中途失败 | 正确错误分类，不假成功；PS 事务恢复，已生成资产保留 |
| V07 | 参数、参考图、自动回贴、编组、返回类型 | 执行采用任务开始时快照，实际结果与 UI 展示设置相符 |
| V08 | 取消与迟到结果、网络重试 | 取消后不自动写 PS；重复 requestId 不重复请求／回贴；未知结果不盲重发 |
| V09 | 插件／Companion 重启后恢复与重跑 | 原输入、refs、mask、参数和版本仍可追溯；缺失时明确阻止错误重跑 |
| V10 | 专业 UI 与 Agent 交替修改 | 读取同一草稿；过期 revision 不覆盖；同一 job 的候选、回贴、反馈双方可见 |
| V11 | 本地调整与真实图像编辑各一次 | 前者是 PS 真实修改，后者来自实际供应商；读回像素／回执供验收 |
| V12 | 一张 COS 样片的目标、执行与返修 | 用户可以判断是否满足角色、本人特征、范围与风格；版本可比较并定向修订 |

M0 通过需要覆盖其原生执行和共享状态相关项；M1 通过需要所有 V01–V12 的适用路径均有证据。fixture 通过与 live 未验证必须分别标记。

## 后续玩法验收

每个工作区至少有：操作路径、schema／工具能力发现、实际后端限制、一份真实案例、失败／取消／恢复路径、UI→Agent 与 Agent→UI 接续。

M3 追加整组照片的样片匹配、批量独立状态、跨来源坐标、输出尺寸／色彩和排版可读性检查。M4 追加图工作流与不同引擎的能力差异、动态参数和中断恢复。

截图或产物应使用专门测试素材，报告中记录使用版本、测试范围和限制；没有测试该项时保留“未验证”，不凭名称或源代码存在把它标成完成。
