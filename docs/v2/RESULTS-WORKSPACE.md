# 候选对比与修订草稿

本模块补齐 M1 的历史任务对比和返修入口。实现位于 `apps/ls-studio/plugin/studio-results-014.js` 与 `companion/capabilities/result-drafts.js`。真实 Photoshop 面板与真实供应商流程仍由集成人在最终提交上验收；本说明不代表已经通过该门禁。

## 操作方式

在专业页选择历史图像任务，再选择候选。A 显示该任务快照中 `context.baseAssetId` 指向的原输入，B 显示所选候选；可以切换 A、B、并排及适应／2×／4× 查看。当前草稿或当前 PS 画布变化不会替换 A。图像缺失、读取失败或解码失败会显示原因并提供重新读取入口。

- **从原输入另建草稿**：复制任务快照的参数和输入，创建新的共享草稿。
- **以候选作参考另建草稿**：在上述副本的参考图列表末尾追加所选候选，角色为 `reference`；不丢弃原有参考。

候选没有 Photoshop 抓图来源，因此不能替换 `baseAssetId` 或冒充新的 PS 捕获。两种操作均保留原图、选区蒙版、文档引用、坐标变换、保留项、生成参数、编译后的配方指令、配方版本哈希和回贴设置。不会重新编译配方。

模型继承先保留快照中显式指定的 `params.model`；未指定时，使用已记录的 `job.provider.model`。两者按去掉 `models/` 前缀和首尾空格后的值比较，矛盾或已记录模型格式异常时返回 `MODEL_CONTEXT_CONFLICT`，不会替换显式请求模型。

取消后迟到的结果可能只有结果记录中的模型，而没有任务级 `job.provider`。此时，从原输入派生会读取各结果资产，校验结果与资产均属于原任务，再核对 `result.provider.model` 与资产 `source.provider.model`。两处都有值时必须一致；有一处记录即可作为该结果的模型证据。全部结果的模型都有记录且一致时，补为新草稿的显式模型；多个结果模型不同，或仅部分结果有模型时，返回 `MODEL_CONTEXT_CONFLICT`，用户可以明确选择一个候选继续。

候选模式只使用所选候选的模型证据，不借用其他候选的模型。其模型与显式请求或任务级记录冲突时也返回 `MODEL_CONTEXT_CONFLICT`。现有显式参数或任务级记录仍可为缺少模型记录的旧候选提供预算依据；所有相关位置都没有模型时，候选模式返回 `REFERENCE_LIMIT_UNKNOWN`。原输入模式没有任何模型证据时保持未设置，用户应在运行前明确选择。两种模式都不会读取当前服务默认模型来填补历史记录。

用户确认并修改新草稿后，再明确触发生成。另建草稿本身不会生成或回贴；如果原任务开启了 `autoApply`，新草稿会保留该设置，后续明确运行仍可能自动回贴。原文档或历史状态已变化时，现有回贴校验仍会拒绝过期输入；需要用户明确重新捕获，模块不会自动刷新或重绑定文档。

当前草稿存在未保存修改时，界面要求先保存、另存或重新载入。如果创建期间用户继续编辑，创建结果会加入草稿列表，但当前输入保持不变。

## 共用接口

HTTP：`POST /studio/call`，使用现有本地访问限制与 `X-PXDLS-Agent: 1` 请求头。

```json
{
  "operation": "deriveDraft",
  "arguments": {
    "jobId": "job-id",
    "mode": "candidate-reference",
    "resultId": "result-id"
  }
}
```

原输入模式使用 `"mode": "original"` 并省略 `resultId`。MCP 使用 `studio_derive_draft`，参数完全相同。两条入口调用同一服务；HTTP 强制记录 `source: ui`，MCP 强制记录 `source: agent`。

返回新的 `CapabilityDraft`：新 ID、revision 1。原任务快照及原草稿保持不变；后续操作使用现有 `studio_get_draft`、`studio_update_draft`、`studio_run`。存储格式不变，不新增单独的 UI 草稿或执行器。

已持久化的图像任务均可派生，包括失败、取消和 `recovery-required` 状态。另建草稿不会重试、恢复或改变原任务状态。用户后续明确运行新草稿才会创建新任务。迟到候选仍需通过所属任务、资产、模型证据和预算校验；恢复模型只会设置新草稿，不会为旧任务补写完成记录或触发回贴。

## 边界与验证

创建前读取并校验全部原始资产，检查来源及尺寸一致性；候选还必须属于所选任务。资产丢失或损坏时返回明确错误，不创建不完整草稿。

追加候选时，参考图上限和供应商输入预算包含原图、蒙版、已有参考及新增候选。使用 `provider.describe({model})` 查询所继承模型的预算；缺少历史模型、adapter 返回不同模型或没有完整数量／字节预算时，返回 `REFERENCE_LIMIT_UNKNOWN`。超过数量或字节预算返回 `REFERENCE_LIMIT`。两种情况均可先从原输入另建草稿，再明确调整参考或模型；不会静默删除参考。原输入模式不要求供应商已配置。

自动化覆盖服务、HTTP/MCP、界面控制器与比较视图：快照不随现草稿变化、来源及配方保留、未保存编辑保护、旧图片请求隔离、缺失资产、候选归属及预算失败，以及从失败／取消／不确定任务派生时不重试原任务。取消回归通过真实服务的运行、取消、接收迟到结果和派生链验证两种模式恢复模型，并覆盖缺失模型、多个结果冲突和结果／资产来源不一致。测试使用专用小图和模拟供应商，无真实生成或 PS 写入。最终还需实际 UXP 中的选择、滚动放大、A/B、返修接续与既有回贴流程验收。
