# COS 照片修图

从用户的照片和表达目标出发，用 `photoshop-use` 读取现场并执行支持的操作。先判断是在诊断画面、准备草稿，还是已经授权执行修图；沿用用户已给出的范围和偏好。

## 把需求变为一次可检查的编辑

读取实际画面，结合已有上下文写清：当前问题、要改变的位置、目标效果、必须保留的内容，以及参考图分别提供什么信息。看不到的细节不要臆测；预览分辨率不足时说明判断限度。

只修改与本次请求有关的特征。人物身份、表情、身形、肤色、角色设定、服装纹样、道具文字是否改变，以用户意图为准；不要把瘦脸、放大眼睛、磨皮或美白当成所有人像的默认步骤。保留毛发、材质纹理、自然光影等要求应写入 context.preserve，必要时也进入具体编辑指令。

局部问题优先利用用户已有的实际选区，明确边缘、遮挡关系和周围需要保留的区域；工具未能取得选区时，不假装已经隔离目标。整图光影或风格变化使用明确的整图范围。可将相互独立的改动分轮处理，让每次结果都能单独比较和撤回。

参考图使用托管 assetId，并区分用途：`identity` 对齐人物或角色身份，`style` 参考光色与质感，`structure` 参考构图或结构，`reference` 为一般参考。写清借鉴什么、原图保留什么；参考图不自动授权换脸、改变动作或替换服装。

## 使用配方与共享草稿

通过 `studio_list_recipes` 搜索，再用 `studio_get_recipe` 阅读完整内容和参数说明。历史配方可能带有强烈重塑或磨皮默认值，先检查是否符合这张照片的要求。参数 0 的含义按该参数说明判断，不假定每个配方的 0 都等于“不做处理”。与当前意图冲突的配方应换用合适配方，或直接写符合需求的提示词。

用 `studio_load_recipe` 把明确数值、原始补充要求和参考图映射写入共享 image.edit 草稿，或直接用 `studio_update_draft` 更新提示词。载入后检查最终 prompt、context、版本和 autoApply 设置。UI 与 Agent 使用同一个草稿；发生版本冲突先读取并协调。保存的配方 ID、sourceHash 和完整参数值用于追溯，不是额外权限。

执行、结果读取、回填及回滚遵循 `photoshop-use` 的工具流程。需要提示词深化且当前会话实际发现了 `cos-effect-prompt` 时，可以按需组合；不要假定外部 Skill 已安装，也不要为了修图修改全局 Skill。

## 用实际像素判断结果

生成后用 `studio_read_asset` 检查候选图，回填后再读取 Photoshop 当前预览。比较本轮请求是否达成，并检查受影响区域：人物辨识度与表情、服饰纹样和道具结构、手部及遮挡、毛发和轮廓边缘、光源方向、肤色与材料质感、背景衔接。把可见缺陷对应到下一轮的具体范围和改动，保留已经成功的部分。

结论分清“草稿已准备”“模型已生成候选”“已回填 PS”“已视觉检查”。预览看不清的微小瑕疵不能声称已验收。提示词中出现高低频分离、液化、修复画笔等词，也不能声称已创建相应 Photoshop 图层或执行原生处理。

当前能力用于既有照片的编辑循环。RAW 冲洗、成组照片统一、色彩管理、版权与交付规格、最终导出等环节，应按实际可用工具和用户要求继续处理；未执行的环节明确保留为待办，不以一张生成候选冒充完成从原片到发布的全流程。
